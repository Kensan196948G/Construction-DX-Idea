# テスト戦略書

## 1. 目的

MVPが業務要件、セキュリティ要件、AI利用制御を満たしていることを確認する。

## 2. テスト種別

| 種別 | 対象 |
|---|---|
| 単体テスト | 入力検査、マスキング、APIレスポンス整形、standalone WebUIブリッジ変換、共有schema |
| 結合テスト | WebUI、Workers、Neon、Claude API、Slack |
| E2Eテスト | 困りごと入力から正式登録、Slack通知まで |
| セキュリティテスト | APIキー非表示、権限、ログ出力 |
| 受入テスト | MVP完了条件 |
| 運用テスト | AI停止、Slack失敗、上限到達 |

## 3. 重要テストケース

| ID | 観点 | 期待結果 |
|---|---|---|
| T-001 | 困りごと入力 | 必須項目を満たすと次へ進める |
| T-002 | 機密情報検出 | メールアドレスに警告が出る |
| T-003 | AI質問 | 最大3問まで生成される |
| T-004 | AI構造化 | 指定項目が返る |
| T-005 | 利用者確認 | 修正後の内容が保存される |
| T-006 | 正式登録 | `submitted` で保存される |
| T-007 | Slack通知 | 登録リンクが通知される |
| T-008 | AI無効 | 手動入力へ切り替えられる |
| T-009 | 利用上限 | 上限到達時にAI実行されない |
| T-010 | APIキー | レスポンスとログに出力されない |
| T-011 | 権限 | 一般利用者はAI設定へアクセスできない |
| T-012 | 監査 | 重要操作が監査ログへ残る |
| T-013 | standaloneブリッジ | 困りごとの本文、回答、構造化下書き、APIステージを正しく変換する |
| T-014 | 共有schema | 未知フィールド、過長文字列、巨大配列を拒否する |
| T-015 | ログ秘匿 | Anthropicキー、Slack Webhook、DB URL、Bearer token、汎用secretをマスクする |

## 4. 受入テストシナリオ

1. 一般利用者がログインする。
2. 困りごとを入力する。
3. 機密情報警告を確認する。
4. AIの追加質問へ回答する。
5. AI構造化結果を確認・修正する。
6. 正式登録する。
7. Slackに通知される。
8. 管理者がステージを変更する。
9. 監査ログとAI利用量が記録される。

## 5. テストデータ方針

- 実在の個人名、案件名、契約金額を使わない。
- ダミーデータで機密情報検出を確認する。
- AIテストではプロンプトバージョンを固定する。
