# 要件定義書

## 1. 目的

`Construction-DX-Idea` は、土木建設業務における困りごとをWebUIから収集し、AIとの壁打ちで整理・構造化したうえで、DXアイデアとして登録・評価・進捗管理するシステムである。

## 2. 基本方針

> 入力・AI整理・進捗管理は Construction-DX-Idea、周知・議論は Slack で行う。

AIは整理、質問、分類、要約、MVP案作成を支援する。採用、却下、セキュリティ判定、本番化の最終判断は人間が行う。

## 3. 対象利用者

| 利用者 | 主な目的 |
|---|---|
| 一般利用者 | 困りごとを入力し、AI整理結果を確認して登録する |
| 現場管理者 | 現場課題を登録し、検討状況を確認する |
| 技術者 | 実現方式、データ、MVP範囲を検討する |
| 研究者 | 課題分類、効果仮説、検証結果を分析する |
| 経営層 | DX投資候補、進捗、効果、リスクを確認する |
| IT・DX部門 | セキュリティ、AI接続、利用量、運用を管理する |
| システム管理者 | 設定、権限、AI機能、監査ログを管理する |

## 4. 業務範囲

### 対象範囲

- 困りごとの入力
- 入力内容の検査、警告、匿名化
- AIによる不足情報の質問
- AIによる構造化
- 利用者による確認、修正、下書き保存、正式登録
- アイデア一覧、詳細、検索、ステージ管理
- Slack通知と議論リンク
- AI利用量、監査ログ、利用制限
- 管理者向けAI接続設定

### 対象外

- Slackからの新規アイデア登録を主導線にすること
- AIによる採用・却下の自動決定
- AIによるセキュリティ最終判定
- APIキーをWebUI、GitHub、DBへ保存すること
- 添付ファイル原文をMVP段階でAIへ送信すること

## 5. 機能要件

| ID | 要件 |
|---|---|
| FR-001 | 利用者はWebUIから困りごとを入力できる |
| FR-002 | 入力画面はDX解決策ではなく業務上の困りごとを入力させる |
| FR-003 | システムは入力内容に機密情報候補が含まれる場合に警告できる |
| FR-004 | システムは必要に応じてAI送信前にマスキングできる |
| FR-005 | AIは不足情報を一度に最大3問程度提示する |
| FR-006 | AIは会話内容を指定項目へ構造化できる |
| FR-007 | 利用者はAI整理結果を修正できる |
| FR-008 | 利用者はAIと再検討できる |
| FR-009 | 利用者は下書き保存できる |
| FR-010 | 利用者は確認後に正式登録できる |
| FR-011 | 正式登録時にSlackへ通知できる |
| FR-012 | 管理者はステージを変更できる |
| FR-013 | システムはAI処理履歴と使用量を記録できる |
| FR-014 | 管理者はAI機能の有効・無効を切り替えられる |
| FR-015 | 管理者は利用上限を設定できる |
| FR-016 | 管理者はAI接続状態、モデル、キー識別情報を確認できる |
| FR-017 | APIキー本体はCloudflare SecretまたはSecrets Storeで管理する |
| FR-018 | AIの応答にも機密情報が含まれないか確認する |
| FR-019 | 人間による意思決定とAI提案との差異を記録できる |
| FR-020 | GitHubを設計書、Issue、実装進捗の正本として利用する |

## 6. 非機能要件

| ID | 分類 | 要件 |
|---|---|---|
| NFR-001 | セキュリティ | Cloudflare Accessで入口を保護する |
| NFR-002 | セキュリティ | APIキーをソースコード、WebUI、DB、GitHubへ保存しない |
| NFR-003 | 監査 | 登録、更新、ステージ変更、アーカイブ、AI実行、設定変更を監査ログへ記録する |
| NFR-004 | 可用性 | AI障害時も下書き保存と既存アイデア閲覧は継続できる |
| NFR-005 | 性能 | 通常画面は3秒以内の応答を目標とする |
| NFR-006 | コスト | 利用者別、機能別、月次のAI使用量を管理する |
| NFR-007 | 保守性 | プロンプトはバージョン管理する |
| NFR-008 | 拡張性 | 将来の複数AIプロバイダー対応を考慮する |
| NFR-009 | プライバシー | AI処理ログに原文全文を保存しない |
| NFR-010 | 操作性 | 非エンジニアでも入力できるウィザード形式とする |

## 7. データ要件

正本として保存する情報は、利用者が確認した構造化結果、人間による意思決定、進捗、監査情報である。AIとの会話全文は永久保存しない。

主要データ:

- ideas
- idea_ai_sessions
- idea_decisions
- idea_comments
- idea_stage_histories
- ai_settings
- audit_logs
- usage_limits

## 8. MVP要件

MVPでは以下を実現する。

1. Cloudflare Accessによるログイン
2. 困りごとの入力
3. AIによる追加質問
4. AIによるアイデア構造化
5. 利用者による修正・確定
6. Neonへの下書き・正式登録
7. アイデア一覧・詳細表示
8. 管理者によるステージ変更
9. Slackへの新規登録通知
10. AI使用量・監査ログ
11. AI機能の有効・無効設定
12. 接続状態・利用上限の管理

## 9. 完了条件

複数の利用者がWebUIから困りごとを入力し、Claude APIによる整理結果を本人が確認・修正して正式登録できること。登録結果がSlackへ通知され、管理者がアイデアの検討ステージを管理できること。
